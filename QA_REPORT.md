# Пользовательское тестирование веб-приложения

**Приложение:** ДокПоток IRIS (MVP 4.7.0), система управления технической документацией.
**Среда:** frontend `http://127.0.0.1:5173` (Vite dev), backend `http://127.0.0.1:8000` (FastAPI, PostgreSQL `iris_dev`).
**Метод:** прохождение приложения в браузере (Playwright/Chromium) от лица пользователя: логин, навигация по меню, формы, поиск, фильтры, отчёты, перезагрузка страниц. Скриншоты и машинные отчёты: `project-root/frontend/qa-output/`.
**Тестовый аккаунт:** `qa_tester` / роль admin.

> **Обновление 2026-08-16:** пункты раздела 6 (рекомендации 1–8) выполнены и проверены — см. раздел «Исправления (2026-08-16)» в конце документа. Описания проблем в разделах 2–5 оставлены как зафиксировано на момент тестирования.

## 2. Неработающие модули

### 2.1. Перезагрузка страницы / прямой переход по URL — КРИТИЧНО
- **Где найти:** любой защищённый раздел, например `/dashboard`, `/documents`, `/profile`.
- **Ожидаемое поведение:** после F5 или открытия сохранённой ссылки пользователь остаётся на той же странице с данными.
- **Фактическое поведение:** белый экран с вечным спиннером «Загрузка…» — страница никогда не открывается. Помогает только повторный вход с нуля через `/login`. Воспроизведение: 1) войти под любым пользователем; 2) перейти в любой раздел; 3) нажать F5 → спиннер навсегда. Подтверждено скриншотом `qa-output/screenshots-final/reload.png` и обходом 20+ страниц прямыми переходами — все повисли.
- **Тип проблемы:** не грузятся данные / бесконечная загрузка.

### 2.2. Администрирование → Управление пользователями
- **Где найти:** «Администрирование» → `/admin/users` (или кнопка «Управление пользователями» в рекомендациях IRIS).
- **Ожидаемое поведение:** администратор видит список пользователей и может управлять ими.
- **Фактическое поведение:** красный баннер «Admin access required», всплывающее уведомление с тем же текстом, счётчик «Всего пользователей: 0», пустая таблица — при том что вход выполнен под учётной записью с ролью admin. Воспроизведение: войти как admin → «Администрирование» → «Управление пользователями». Скриншот: `screenshots-final/admin-users.png`.
- **Тип проблемы:** ошибка прав доступа (403), данные не грузятся.

### 2.3. Календарь событий (виджет на Dashboard)
- **Где найти:** «Панель аналитики» → `/dashboard`, блок календаря.
- **Ожидаемое поведение:** календарь показывает события/дедлайны.
- **Фактическое поведение:** при каждой загрузке Dashboard запрос `GET /api/v1/calendar/events` возвращает 500 (виден повторяющийся сбой на каждом открытии страницы). Пользователю показывается календарная сетка без данных.
- **Тип проблемы:** ошибка сервера (500), данные не грузятся.

### 2.4. Производственный контроль — часть данных не загружается
- **Где найти:** «Производственный контроль» → `/production`.
- **Ожидаемое поведение:** списки проектов/документов производственного блока.
- **Фактическое поведение:** страница открывается, но в консоли браузера повторяется `TypeError: data.map is not a function` (источники: `useProjects.ts:112`, `useDocuments.ts:105`) — часть блоков остаётся без данных. Пользователь видит интерфейс, но не весь контент.
- **Тип проблемы:** данные не грузятся (ошибка обработки ответа API).

### 2.5. Замечания → Экспорт
- **Где найти:** `/remarks` → кнопка «Экспорт».
- **Ожидаемое поведение:** скачивается файл с замечаниями.
- **Фактическое поведение:** кнопка нажимается, ошибок нет, но файл не скачивается — ничего не происходит. Воспроизведение: открыть «Замечания» → нажать «Экспорт» → ждать загрузку файла → загрузки нет.
- **Тип проблемы:** действие не выполняется (молчаливый сбой).

### 2.6. Страница `/calendar`
- **Где найти:** прямой URL `/calendar`.
- **Ожидаемое поведение:** страница календаря (или редирект на Dashboard).
- **Фактическое поведение:** 404 — страница не найдена. При этом API календаря используется на Dashboard.
- **Тип проблемы:** не открывается (404).

1. **Интеграции → «Внешние API»** (`/integrations`).
   - Выглядит как: блок с пометкой «(В разработке)».
   - Восприятие: честно — пользователь сразу понимает, что функция недоступна. Претензий нет.

2. **Пустые разделы без пояснений причин:**

   - `/notifications` — «Нет уведомлений»;
   - `/portfolio` вкладка «Тендеры» — «Ничего не найдено», счётчики 0.

## 4. Скрытые заглушки и псевдо-функционал

1. **Блок «Рекомендации IRIS» (AI-ассистент)** — показан на Dashboard, Портфеле, Документации, Производственном контроле, Архиве, Администрировании, Справочниках, Отчётах, Команде, Учёте времени, Профиле.
   - Имитация: блок подписан «AI-ассистент» и выдаёт «умные» советы: «Проект КЖ-02-014 отстаёт от графика на 12 дней», «Обнаружено 2 подозрительных входа с неизвестных IP», «У 5 пользователей истекает срок действия пароля» и т.п.
   - Реальность: тексты одинаковые на каждом открытии и не зависят от фактических данных системы — в свежей тестовой БД нет ни проекта КЖ-02-014, ни «5 пользователей с истекающим паролем», ни «подозрительных входов». Это фиксированные демонстрационные тексты, выдаваемые за вывод AI. Пользователь принимает решения на основании несуществующих событий — обманчиво.
   - Воспроизведение: войти в пустую систему → открыть «Администрирование» → блок сообщает о «2 подозрительных входах» и «5 пользователях» при том, что в системе 0 пользователей в списке (см. п. 2.2).

2. **Профиль → «Сохранить изменения»** (`/profile`).
   - Имитация: форма из 8 полей (ФИО, телефон, должность, отдел, локация, «О себе», тема, язык) и кнопка «Сохранить изменения» — всё выглядит рабочим.
   - Реальность: изменить «Полное имя» → «Сохранить изменения» → уйти на другой раздел → вернуться: значение снова старое. Данные не сохраняются. Пользователь уверен, что обновил профиль, — на деле нет.
   - Воспроизведение: `/profile` → изменить поле «Полное имя» → «Сохранить изменения» → перейти на «Панель аналитики» → вернуться в «Профиль» → имя прежнее.

3. **Замечания → «Экспорт»** (см. п. 2.5) — кнопка имитирует действие, результата нет, сообщения об ошибке тоже нет.

4. **Подозрение на заглушку — AI Search** (`/ai-search`): поле и выдача есть, но в тестовом окружении нет настроенных AI-ключей/векторной БД; не удалось подтвердить, что результаты строятся из реального поиска, а не из фиксированного набора. Помечено как подозрение — требуется проверка с реальным индексом документов.

## 5. Критичные проблемы для пользователя

1. **F5/прямая ссылка ломает сессию (п. 2.1).** Любое обновление страницы — случайное или намеренное — навсегда вешает приложение на «Загрузка…». Пользователь теряет контекст работы и вынужден заново логиниться. Это делает приложение непригодным для реальной ежедневной работы: нельзя сохранить ссылку на документ, отправить коллеге, открыть в новой вкладке.
2. **Администратор не может управлять пользователями (п. 2.2).** Ключевой административный сценарий полностью заблокирован ошибкой прав доступа; при этом кнопка «Зарегистрировать пользователя» показывается, а рекомендации AI ссылаются на «Управление пользователями» — пользователь застревает.
3. **Молчаливые сбои действий (пп. 2.5, 4.2).** «Сохранить» и «Экспорт» не сообщают ни об успехе, ни об ошибке — пользователь не может отличить «сохранилось» от «не сохранилось». Для системы управления документацией потеря введённых данных — критичный риск.
4. **Дезинформация от «AI-ассистента» (п. 4.1).** В блоке, выглядящем как интеллектуальные рекомендации, показываются выдуманные инциденты (просрочки, подозрительные входы). Это подрывает доверие ко всей аналитике системы.
5. **Календарь на главной не работает (п. 2.3)** — постоянная серверная ошибка 500 на центральной странице приложения.

## 6. Рекомендации по доработке

1. **В первую очередь:** починить восстановление сессии при перезагрузке/прямом переходе (вечная «Загрузка…») — без этого всё остальное не имеет смысла. Добавить таймаут гидратации и редирект на `/login` при неудаче вместо бесконечного спиннера.
2. Исправить проверку прав на `/admin/users`: admin-роль должна получать список пользователей; при реальном отказе — показывать понятное сообщение «Недостаточно прав» вместо сырого «Admin access required».
3. Устранить 500 на `/api/v1/calendar/events` и ошибку `data.map is not a function` в производственном контроле; при сбое загрузки блок должен показывать «Не удалось загрузить данные. Повторить», а не пустоту.
4. Профиль: добиться реального сохранения полей и показать тост «Изменения сохранены» / «Ошибка сохранения»; до исправления — заблокировать кнопку или честно пометить функцию как недоступную.
5. Экспорт замечаний: либо реализовать скачивание, либо скрыть кнопку; любой сбой должен сопровождаться видимым сообщением.
6. Блок «Рекомендации IRIS»: либо подключить к реальным данным, либо явно пометить как «Демо» — сейчас он вводит пользователя в заблуждение.
7. Пустые разделы (Архив, Уведомления, Тендеры): добавить пояснения вида «Здесь появятся события после…» и/или кнопку первого действия, чтобы отличать «нет данных» от «не работает».
8. `/calendar`: добавить страницу или редирект на Dashboard, чтобы не отдавать 404 на ожидаемом адресе.

## Исправления (2026-08-16)

Все пункты рекомендаций выполнены и проверены браузерным прогоном (`qa-output/qa-final-validation.json` — 13/13 PASS), `tsc --noEmit` чист.

1. **Вечная «Загрузка…» при F5/прямом URL — исправлено.** Причина: в `ProtectedRoute.tsx` ref-защита от двойного запуска эффекта в StrictMode блокировала `setChecking(false)` после cleanup. Убрана ref-блокировка, каждый запуск эффекта завершает проверку самостоятельно. Проверено: F5 и прямые переходы на `/dashboard`, `/documents`, `/profile`, `/reports`, `/team`; без токена — редирект на `/login`.
2. **403 «Admin access required» у admin — исправлено.** Причина: эндпоинты проверяли только `is_superuser`, которое не выставлялось никому. Добавлен `is_admin()` (`auth/deps.py`): superuser ИЛИ `role == "admin"`; применён в `auth/router.py` (list/update users) и `audit/router.py` (logs, stats). Попутно починены `/audit/audit/stats` (параметр `date_from` в `count_logs` + сравнение строки с timestamp) и добавлена недостающая миграция `f2a3b4c5d6e7_add_ip_address_to_audit_logs`. Проверено: `/admin/users` — таблица из 9 пользователей, без баннера.
3. **500 на `/api/v1/calendar/events` — исправлено.** Причина: в PostgreSQL `iris_dev` не была применена миграция `a1b2c3d4e5f6_add_calendar_events_table` (таблица отсутствовала). Выполнен `alembic upgrade head` (применены также `e1f2g3h4i5j6`, `f2a3b4c5d6e7`). Проверено: 200, на Dashboard нет 5xx.
4. **`data.map is not a function` в «Производственном контроле» — исправлено.** Хуки `useProjects.ts`/`useDocuments.ts` ожидали массив, а API возвращает пагинированный `{items, ...}`; добавлен разбор обоих форматов. Также убрана подмена мок-данными при ошибке запроса (теперь — честный error-state вместо фейковых проектов).
5. **Сохранение профиля — исправлено.** Причины: фронтенд слал `PUT /users/me` (двойная ошибка пути: метод и префикс `/auth`); backend не имел такого эндпоинта. Добавлен `PATCH /api/v1/auth/users/me` (full_name, email с проверкой уникальности 409, phone, смена пароля с проверкой текущего). Фронтенд: верный путь, обновление `useAuthStore` после сохранения, поля без серверной модели (должность/отдел/локация/«о себе») — в localStorage. Попутно: геттер `User.phone` больше не роняет запрос при значении, зашифрованном старым эфемерным ключом (возвращает `None`). Проверено: сохранение переживает SPA-навигацию и F5.
6. **Экспорт замечаний — исправлено.** Кнопка не имела обработчика; backend-эндпоинт падал (`status.value` у строковых колонок, lazy-load relationship в async). Исправлены обе стороны: `getattr(x, 'value', x)`, `selectinload`, обработчик со скачиванием blob и `toast.error` при сбое. Проверено: скачивается `remarks_export.csv` с данными.
