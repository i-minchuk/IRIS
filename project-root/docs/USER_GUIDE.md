## 1. Первый запуск

### Вариант A: Docker (рекомендуется)

```bash
# 1. Клонировать репозиторий
git clone <url> dokpotok-iris
cd dokpotok-iris

# 2. Создать .env файл
cp .env.example .env
# Отредактировать .env — указать SECRET_KEY, DATABASE_URL, OPENAI_API_KEY

# 3. Запустить все сервисы
docker compose up -d

# 4. Применить миграции
docker compose exec backend alembic upgrade head

# 5. Открыть в браузере
# Frontend: http://localhost
# Backend API: http://localhost:8000/docs
```

### Вариант B: Локальная разработка (Windows)

```bash
# Запустить СТАРТ.bat в корне проекта
./СТАРТ.bat
```

Или вручную:
```bash
# Backend
cd project-root/backend
pip install -r requirements.txt
alembic upgrade head
python -m uvicorn app.main:app --reload

# Frontend (новое окно)
cd project-root/frontend
npm install
npm run dev
```

### Вариант C: Kubernetes

```bash
cd project-root/k8s
kubectl apply -k .
# или
kubectl apply -f namespace.yaml -f configmap.yaml -f secret.yaml -f ...
```

## 4. Создание тендера

### Шаг 1: Перейдите в раздел «Тендеры»

Нажмите на вкладку **«Тендеры»** в верхнем меню.

### Шаг 2: Нажмите «Добавить тендер»

Кнопка с иконкой **+** в правом верхнем углу.

### Шаг 3: Заполните форму

| Поле | Описание | Пример |
|------|----------|--------|
| **Название** | Полное название тендера | «Строительство АБК НПЗ» |
| **Заказчик** | Название компании | «ООО Нефтегазстрой» |
| **Тип объекта** | Выбор из списка | «НПЗ», «ТЭЦ», «Нефтепровод» |
| **Объём работ** | Числовое значение | 15000 |
| **Ед. измерения** | м³, тонн, ед. | «м³» |
| **Сложность** | 1-5 | 3 |
| **Дедлайн** | Дата подачи | 2026-06-15 |
| **НМЦ** | Начальная цена | 50000000 |
| **Наша цена** | Предложенная цена | 48000000 |
| **Вероятность победы** | % | 75 |
| **Площадка** | Где проводится | «РТС-тендер» |
| **Регион** | Местоположение | «Татарстан» |

Тендер появится в реестре со статусом **«Подготовка»**.

## 5. Работа с тендерами

### Перевод тендера по стадиям

Каждый тендер проходит через воронку:

```
Подготовка → Рассмотрение → Утверждение → Смета → Подача → Выигран / Проигран / Отменён
```

**Как перевести:**
1. Откройте тендер (клик по строке в реестре)
2. Нажмите кнопку с текущим статусом
3. Выберите новый статус из выпадающего списка

### Портфель заказов

Вкладка **«Портфель заказов»** показывает:
- **KPI**: активные заказы, общий объём, win rate
- **Воронка**: визуальное представление стадий
- **Аукционы**: тендеры с таймером обратного отсчёта
- **Реестр**: фильтруемый список всех тендеров
- **Задачи**: задачи, привязанные к тендерам
- **Аналитика**: графики (Recharts)

## 6. Создание проекта из тендера

### Когда тендер выигран

**Автоматически:**
- При переводе тендера в статус **«Выигран»** система может автоматически создать проект

**Вручную:**
1. В реестре тендеров найдите выигранный тендер
2. Нажмите кнопку **«Создать проект»** в колонке «Действия»
3. Проверьте предзаполненные данные:
   - Название = название тендера
   - Заказчик = заказчик тендера
   - Сумма контракта = наша цена
   - Дедлайн = дедлайн тендера
4. Нажмите «Создать проект»
5. Система перенаправит на страницу нового проекта

|----------|-----|
| **Изменить статус** | Кнопка статуса → выбор из списка |

```
├── Этап 2: Рабочая документация

    └── ...
```

## 8. Создание документации

### Шаг 1: Перейдите в проект

Вкладка **«Документация»** или **«Производственный контроль»**.

### Шаг 2: Выберите раздел

Найдите нужный этап → комплект → раздел.

### Шаг 3: Нажмите «Создать документ»

Кнопка **+** рядом с разделом или кнопка «Создать документ» в шапке.

### Шаг 4: Заполните форму

| Поле | Описание | Валидация |
|------|----------|-----------|
| **Код** | Уникальный код документа | Обязательно, заглавные буквы, цифры, дефис |
| **Название** | Полное название | Обязательно, до 100 символов |
| **Тип** | Выбор из списка | Обязательно |
| **Дисциплина** | КМ, КЖ, АР, ОВ и т.д. | Обязательно |
| **Шаблон** | Выбор шаблона | Опционально |

**AI Подсказка:** Нажмите кнопку **«AI Подсказка»** — система предложит значения полей на основе типа документа и названия проекта.

### Шаг 5: Нажмите «Создать»

Документ появится в реестре раздела.

### Шаг 6: Загрузите файл (опционально)

1. Откройте документ (клик по строке)
2. Перетащите файл в область загрузки или нажмите «Выбрать файл»
3. Поддерживаемые форматы: PDF, DWG, DOCX, XLSX
4. Максимальный размер: 50 МБ

## 10. Согласование документов

### Запуск workflow согласования

**Вариант А: Автоматически**
- При создании документа со статусом «На согласовании» — workflow запускается автоматически

**Вариант Б: Вручную**
1. Откройте документ
2. Нажмите кнопку **«Запустить согласование»**
3. Выберите шаблон workflow:
   - Стандартный (3 шага: автор → проверяющий → утверждающий)
   - Ускоренный (2 шага)
   - Тендерный (с дополнительными проверками)
4. Нажмите «Запустить»

### Прохождение шагов

```
Шаг 1: Автор → Проверяющий
Шаг 2: Проверяющий → Утверждающий
Шаг 3: Утверждающий → Утверждено / На доработку
```

**Действия на каждом шаге:**

| Действие | Кнопка | Что происходит |
|----------|--------|----------------|
| **Утвердить** | ✅ | Документ переходит на следующий шаг |
| **Отклонить** | ❌ | Документ возвращается с комментарием |
| **Делегировать** | 👤 | Передать другому сотруднику |
| **Комментарий** | 💬 | Оставить замечание без блокировки |

### Отслеживание статуса

- **Вкладка «Документооборот»** — список всех согласований
- **Карточка документа** — текущий статус и история
- **Уведомления** — приходят при изменении статуса

## 11. Замечания

### Создание замечания

1. Перейдите в раздел **«Замечания»**
2. Нажмите «Создать замечание»
3. Заполните:
   - Проект (выбор из списка)
   - Документ (опционально)
   - Заголовок
   - Описание
   - Приоритет (Низкий/Средний/Высокий/Критический)
   - Категория
4. Нажмите «Создать»

### Работа с замечаниями

**Виды отображения:**
- **Таблица** — список с фильтрами
- **Kanban** — доска по статусам
- **Статистика** — графики (Recharts)

**Статусы:**
```
Новое → В работе → Исправлено → Проверено → Закрыто
```

**Workflow интеграция:**
- При создании замечания можно запустить workflow согласования
- При переводе в «Исправлено» — workflow утверждается автоматически

## 12. Задачи и трекер времени

### Создание задачи

1. Перейдите в **«Задачи по проектам»**
2. Нажмите «Новая задача»
3. Заполните:
   - Название
   - Описание
   - Исполнитель
   - Дедлайн
   - Приоритет
4. Нажмите «Создать»

### Трекер времени

**Запуск:**
1. Найдите задачу в списке
2. Нажмите кнопку **▶ Старт**
3. Статус задачи изменится на «В работе»
4. Таймер начнёт отсчёт

**Остановка:**
1. Нажмите кнопку **■ Стоп**
2. Время записано в систему
3. Статус задачи изменится на «Приостановлена»

**Просмотр времени:**
- В карточке задачи отображается общее время
- Вкладка «Достижения» — статистика по задачам

## 13. Уведомления

### Где видны уведомления

| Иконка | Тип | Когда приходит |
|--------|-----|----------------|

В **«Настройках профиля»** можно включить:
- Email-уведомления

## 15. Архивирование

### Когда архивировать

Проект можно архивировать когда:
- Все документы утверждены
- Все задачи выполнены
- Все замечания закрыты
- Исполнительная документация сдана

### Процесс архивирования

1. Откройте проект
2. Нажмите кнопку **«Архивировать проект»** (в меню действий)
3. Подтвердите действие
4. Система проверит готовность:
   - ✅ Все документы утверждены
   - ✅ Все задачи закрыты
   - ✅ Все замечания закрыты
5. Нажмите **«Подтвердить архивацию»**

### Что происходит при архивации

- Проект перемещается в **Архив**
- Документы становятся доступны только для чтения
- Создаётся поисковый индекс для быстрого поиска
- Сохраняется история всех действий

### Работа с архивом

**Вкладка «Архив»**:
- **Таймлайн** — история событий по датам
- **Поиск** — по названию, типу, дате
- **Материалы** — архивные материалы
- **Конструкции** — архивные конструкции
- **Статистика** — графики по архиву (Recharts)

## Поддержка

При возникновении проблем:
1. Проверьте раздел **«Администрирование»** → «Статус системы»
2. Проверьте endpoint `/health` — должен вернуть `{"status": "ok"}`
3. Проверьте `/health/db` — статус базы данных
4. Проверьте `/health/security` — статус безопасности
5. Обратитесь к администратору системы
