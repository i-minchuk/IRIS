> Составлено 2026-10-01 (версия 4.8.0). Полный аудит по коду.
> Приоритет: **P1** — влияет на пользователей сейчас, **P2** — заметно при определённых сценариях, **P3** — инфраструктура под будущие интеграции.

## P1 — влияет на пользователей сейчас

### 1. Восстановление пароля не завершено
- **Где:** `backend/app/modules/auth/router.py:646`
- **Что:** токен сброса генерируется и сохраняется, но письмо с ссылкой не отправляется (нет SMTP). Пользователь не может сам восстановить пароль — только через админа.
- **Чинить:** подключить SMTP-конфиг (хост, порт, логин, пароль из .env), отправлять письмо через `app/core/email.py`, заполнить шаблон ссылки `{FRONTEND_URL}/reset-password?token=...`.

### 2. Аналитика: пустые серии спарклайнов
- **Где:** `backend/app/modules/analytics/router.py:656-660` (`/analytics/sparklines`)
- **Что:** три серии из четырёх — `schedule_dev` (отклонение графика), `fpy` (дефектность), `shipments` (отгрузки) — всегда `[0]×30`. На Панели аналитики KPI-карточки «Ср. срок согласования», «% победы», «Просроченные документы» показывают нули.
- **Чинить:** определить реальные источники: `schedule_dev` — из сроков согласования документов vs плановых дат; `fpy` — из замечаний/ревизий; `shipments` — из дат отгрузки в производстве (см. п. 5).

### 3. Аналитика: FPY и отгрузки в KPI-плитках
- **Где:** `backend/app/modules/analytics/router.py:304` (FPY), `:309` (отгрузки недели)
- **Что:** плитки «Дефектность FPY» (всегда 0.0) и «Отгрузки недели» (план/факт 0) без источника данных.
- **Чинить:** вместе с п. 2, единая логика расчёта.

### 4. Календарь: дни рождения всегда пустые
- **Где:** `backend/app/modules/calendar/router.py:261`
- **Что:** у модели `User` нет поля даты рождения — эндпоинт всегда возвращает `[]`.
- **Чинить:** миграция: добавить `birthdate: Optional[date]` в `auth/models.py` + поле в профиле пользователя (фронт) + вывод здесь.

### 5. Производственный контроль: карта процесса с пустыми KPI
- **Где:** `backend/app/modules/production/seed.py` (зашит в код), значения KPI `"value": ""`
- **Что:** схема процесса (этапы, операции, документы, сотрудники) — статичная константа; метрики по операциям пустые.
- **Чинить:** решить: либо вынести карту в БД (таблицы процессов/операций) и считать KPI из реальных данных, либо минимум — заполнить значения из задач/документов.

## P2 — заметно в отдельных сценариях

### 6. Тендеры: «Статус закупки» — мок
- **Где:** `backend/app/modules/tenders/router_extended.py:485` (`_estimate_materials`)
- **Что:** материалы и сроки поставки по тендеру вычисляются эвристикой по типу проекта — не реальные данные.
- **Чинить:** связать с модулем SRM (заявки на закупку/заказы), когда там появятся реальные позиции.

### 7. Отчёты: генерация возвращает фиктивный URL
- **Где:** `backend/app/tasks/reports.py:8` (Celery)
- **Что:** задача возвращает `url: /reports/123.pdf`, файла нет.
- **Чинить:** реализовать генерацию (reportlab/weasyprint) и складывать в storage; до этого — возвращать честную ошибку, а не фиктивный URL.

### 8. Экспорт данных (Celery) не реализован
- **Где:** `backend/app/tasks/reports.py:22`
- **Что:** задача-заглушка, ничего не экспортирует.
- **Чинить:** реализовать выгрузку моделей в csv/xlsx (pandas/openpyxl уже есть в окружении).

### 9. Уведомления: email/push не отправляются
- **Где:** `backend/app/tasks/notifications.py:8,22,36`; `backend/app/core/email.py`, `core/telegram.py`
- **Что:** задачи возвращают `status: completed`, ничего не отправляя; email/telegram — печать в консоль `[EMAIL MOCK]`.
- **Чинить:** подключить SMTP (см. п. 1) и Telegram-бота (токен из .env); уведомления в приложении (внутренние) работают.

### 10. Документы: Celery-задачи PDF и обработки файлов
- **Где:** `backend/app/tasks/documents.py:8,22`
- **Что:** заглушки под генерацию PDF и обработку загруженных файлов.
- **Чинить:** парсинг DOCX/PDF уже есть (`app/parser`), осталось завернуть в задачи; генерация PDF — по требованию.

## Не заглушки (для ясности)

- **Просмотрщики документов `mock={true}`** — задуманное поведение: документ без файла показывает форматную заглушку.
- **Мок календаря** (`frontend/features/calendar/api/calendar.ts:81`) — возвращает `[]`, вымышленные события зачищены намеренно.
- **Статичный глоссарий** — пуст по задумке; наполнение через «Сгенерировать из документации» / «Добавить вручную».
- **Демо-сид** (`db/demo_seed.py`) — осознанная фича демо-режима с защитой от записи в рабочую БД.
- **Геймификация/AI-интеграции** — реализованы, но зависят от внешних ключей (OpenAI/GigaChat): без ключа работают в деградированном режиме.

3. Пункты 1, 9 — одним блоком «SMTP-уведомления».
4. После исправления — удалить пункт из списка (или перенести в «Не заглушки» с пояснением).
