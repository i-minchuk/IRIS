# Матрица доступов по ролям (RBAC)

> Утверждена 2026-10-05. Администратор (`admin` / `is_superuser`) имеет
> полный доступ ко всему функционалу системы без ограничений — это правило
> приоритетно при любых проверках.

## Роли

| Роль | Slug | Назначение |
|------|------|------------|
| Администратор | `admin` | Полный доступ ко всему |
| Директор | `director` | Управление, аналитика, финансы |
| ГИП | `gip` | Контроль и утверждение документации |
| Технический документооборот | `doc_controller` | Ведущий техдокументации: запуск маршрутов, статусы, архив |
| Инженер | `engineer` | Разработка документов, задачи |
| Проектировщик | `designer` | Разработка документов (свои шаги согласования) |
| ПТО | `pto` | Производственно-технический отдел, исполнительная документация |
| МТО | `mto` | Полный цикл закупок (заявки, заказы, поставщики, контракты) |
| Логистика | `logistics` | Доставки: сроки, транспорт, отслеживание поставок |
| Кладовщик | `storekeeper` | Приёмка поставок, документы по материалам |
| Монтажник | `installer` | Монтаж: чертежи своего объекта, задачи, замечания |

Неизвестная/устаревшая роль → минимальный доступ (Dashboard, документы,
задачи, учёт времени, достижения — только чтение где не указано иное).

## Матрица

ограниченные действия · **—** нет доступа (API вернёт 403, раздел скрыт в меню).

## Бизнес-процессы

- **Закупочная цепочка:** МТО создаёт заявку и заказ → Логистика организует
  доставку → Кладовщик принимает на складе/объекте. Все трое видят SRM,
  каждый свою часть; финансы видят только МТО и Директор.
- **Документооборот:** Тех. документооборот запускает маршрут и ведёт статусы
  и архив → Инженер/Проектировщик проходят свои шаги → ГИП контролирует и
  утверждает финальный шаг → Директор видит весь процесс.
- **Монтаж:** Монтажник видит чертежи своего объекта (PDF/DWG прямо в системе),
  получает задачи, может создавать замечания с объекта.

## Реализация

- **Этап 1:** роли в enum, центральный модуль `app/core/permissions.py`,
  guards на уровне роутеров через `api/router.py` (нет доступа → 403).
- **Этап 2:** скрытие финансовых полей в ответах API (цены тендеров, контракты)
  для ролей без права `finance.read`; фильтрация меню и страниц на фронтенде.
- **Этап 3 (текущий):** объектный уровень — scoped-роли (`documents.scoped`,
  сейчас — монтажник) видят документы, задачи и замечания только своей
  привязки (автор/проверяющий/утверждающий/исполнитель документа; задачи —
  где пользователь исполнитель); write-guards SRM: заявки/контракты/справочники
  — МТО, заказы — МТО и Логистика, приёмка (статусы delivered/inspection/
  accepted/rejected) — Кладовщик, счета — МТО.

Код прав: `permissions.py`, функции `get_permissions(role)`,
`require_permission(perm)` (admin/superuser — всегда разрешено).
