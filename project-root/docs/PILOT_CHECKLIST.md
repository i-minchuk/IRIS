# Чек-лист запуска тестовой группы (рабочий режим prod)

Рабочий режим: реальные данные, полный функционал, файловое логирование,
метрики, кнопка «Сообщить о проблеме».

## 1. Включение prod-режима

- [ ] В `.env` (`project-root/backend/.env`) задать `MODE=prod` (или не задавать — prod по умолчанию).
- [ ] Проверить, что `SECRET_KEY` сгенерирован (мин. 32 символа, не дефолтный).
- [ ] Настроить `DATABASE_URL` (PostgreSQL для стенда, SQLite допустим для малой группы).
- [ ] Ограничить `BACKEND_CORS_ORIGINS` реальными доменами.
- [ ] Запустить backend и убедиться в логе старта строки `Режим работы: prod`.

```bash
cd project-root/backend
export MODE=prod
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

- [ ] Прогнать smoke: `python scripts/smoke_modes.py --base-url http://127.0.0.1:8000 --mode prod` — все `[OK]`.

## 2. Создание пользователей тестовой группы (10–20 человек)

- [ ] Зарегистрировать первого администратора (первый пользователь / через сид-скрипт).
- [ ] Через раздел «Администрирование» завести остальных пользователей, назначить роли.
- [ ] Раздать учётные данные и ссылку на систему участникам.
- [ ] Убедиться, что демо-пользователь `demo@iris.local` в базе отсутствует
      (в prod автосид не выполняется; при переносе базы из demo — удалить его).

## 3. Загрузка реальных данных

- [ ] Следовать `docs/DATA_LOADING.md` (проекты → документы → замечания/задачи).
- [ ] Проверить, что счётчики на дашборде и в администрировании отражают реальные данные.

## 4. Логи и метрики

- [ ] Логи пишутся в `project-root/backend/logs/`: `app_YYYYMM.log` (INFO+), `error_YYYYMM.log` (ERROR), ротация 10 МБ × 5 файлов.
- [ ] Метрики Prometheus доступны на `/metrics` (время отклика, ошибки, запросы).
- [ ] Настроен сбор логов/метрик (Prometheus + Grafana из корневого compose — опционально).
- [ ] Ежедневные бэкапы БД (systemd timer, хранение 30 дней) — см. `docs/RELEASE_CHECKLIST.md`.

## 5. Сбор обратной связи

- [ ] Проверить, что в шапке есть кнопка «Сообщить о проблеме» (видна только в prod).
- [ ] Тестовое обращение: заполнить форму → тикет появляется в разделе поддержки (`/api/v1/support/tickets`).
- [ ] Назначить ответственного за разбор тикетов и `error_YYYYMM.log` (регулярность: ежедневно в первую неделю).
- [ ] Канал для срочных вопросов группы: мессенджер/почта (указать участникам).

## 6. Критерии готовности к старту

- [ ] Smoke-скрипт prod — все `[OK]`.
- [ ] Вход/выход, создание проекта и документа работают под реальным пользователем.
- [ ] Экспорт замечаний и архива возвращает файлы (не 403).
- [ ] Тикет обратной связи создаётся и виден администратору.
- [ ] Бэкап БД настроен и проверен восстановлением на копии.

## Откат

Если что-то пошло не так: остановить backend, восстановить БД из последнего
бэкапа, перезапустить. Переключение на demo для разбора проблемы —
`MODE=demo` без изменения кода.
